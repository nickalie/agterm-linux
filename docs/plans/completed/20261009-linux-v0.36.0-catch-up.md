### Fixed on the way

- `TerminalClipboard` used Darwin's `F_SETNOSIGPIPE`, so `agtermCore` did not build on Linux.
- The portable markdown parser dropped link targets, so no Linux HUD link was underlined or clickable.
- `hud.sh`'s `cellcount` overwrote the body's line count, so a multi-line plain panel was centered wrong under dash.
- An `overlay.resize --full` on a HUD was not refused on Linux.
- The Linux tree re-projection dropped `indexUnsaved` (since v0.35.1) and would have dropped `linkOpenMode`;
  `LinuxTreeProjectionTests` compared a hand copy, and now calls the projection itself.
- The Linux HUD parser and the remote HUD mirror are copies that had to learn `sticky` and `frame`.

### Linux adaptations

- A terminal link opens on Ctrl-click; a HUD link too, through a capture-phase gesture on the deck that hands the
  click to the panel's surface. The pointer stays an arrow over a HUD link: the panel takes no input.
- WebKitGTK reports `window.close()` through the `close` signal; the plugin ABI moved to 4 for the `closed` callback.
- Attach Remote is a palette row and Ctrl+Shift+R. `linuxCompatibilityUnbound` vacates the chord for a keymap that
  already spends it, as upstream's parser does with ⌘⇧R. `remotes.conf` is read when the palette opens.
- The in-app picks resolve through a callback (`pickInApp`): the GLib loop drains no Swift Concurrency executor.
- The replay reads argv and cwd from `/proc`; a root-owned foreground such as `sudo` is refused for its unreadable cwd.
- A HUD panel's surface is pinned to 8/6 padding, which the metrics now report instead of zero.
- `clipboard set` finds the payload's zmx in `libexec`.

### macOS-only, exempt

- The sidebar remote icon (#710): GTK rebuilds the row on every connection change already.
- Hosted test windows without animation (eda93d59) and the search bar's `HudClickCover`: the GTK search bar sits
