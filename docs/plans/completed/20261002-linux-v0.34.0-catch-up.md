### Linux adaptations

- WebKitGTK names no frame on a script message, so the native handler is registered only in agterm's isolated
  world, which page scripts and frames cannot reach. A `--js` page's `agterm.request` relays through
  `window.postMessage` to an isolated-world listener that accepts only messages whose source is the top window.
  The `v034-html-bridge` scenario sends a spoofed request from a frame and fails if it lands.
- A page request waits one main-loop turn before it dispatches, so a command closing its own page never runs
  inside WebKit's signal; `zmx.tree`/`zmx.attach` run on a worker thread as over the socket.
- The page owns the font keys when focus sits outside the active session's terminals and a page covers it; GTK
  has no first responder, so that stands in for macOS's web-view-in-responder-chain test.
- A waiting remote pane leaves Ctrl+Shift chords to Ghostty, the Linux counterpart of macOS letting Command
  chords through. GTK key events carry no repeat flag, so every retry press is owned until release instead.
- Reconnect probes run `LinuxRemoteCommandRunner` on a worker thread from the presentation service's remote tick.
  Only the wrapper, key classification and lost-link notice are covered by tests here; a live ssh drop was not
  exercised, as no remote agterm host is available to this run.

### macOS-only, exempt

- Control-click opens the sidebar row menu (#669): an AppKit `NSTableView` quirk; GTK rows already open
  their menu on a secondary click, and Ctrl-click has no context-menu meaning on Linux.
