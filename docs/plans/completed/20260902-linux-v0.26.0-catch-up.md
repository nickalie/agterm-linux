### Carried portable core fixes

- `agtermctl version` resolved its own path with `_NSGetExecutablePath`; `/proc/self/exe` off Darwin.
- `WindowLibrary.strayWindowFileIDs` read an unenumerable windows directory as "no strays" on Linux:
  corelibs-foundation answers an empty listing where Darwin throws when the path is not a directory, so
  both the claim walk and the launch inventory reported themselves complete. Requiring a directory first
  gives the two platforms one answer. Upstreamable as-is.
- `AgentHooksInstall` re-widens the nine symbols upstream narrowed in #474; the Linux Integrations page is
  the downstream consumer upstream's own note records.
- Test-side platform guards: Glibc import, the 0500-mode tests that root ignores, the `/bin/tcsh` case.

### zmx: live and remote sessions

Ported in full rather than exempted. The host-free half is inherited; the Linux host supplies:

13. `scripts/setup-linux.sh` builds pinned zmx with the same zig the libghostty build uses, stages it beside
    the vendored ghostty, and `scripts/stage-linux.sh` puts it in the payload; DEB, RPM and AppImage carry it.
14. `LinuxZmxLaunch` — executable resolution, `getpwuid` login shell, resources and state directory, and the
    per-pane configuration.

17. Launch reap, pane claims and the restore-mode latch at startup.
18. `restore.mode` read and write, `zmx.list`, `zmx.prune`, `zmx.kill`.
19. `zmx.tree` and `zmx.attach` over ssh, plus the remote-session row in the sidebar.
20. Settings ▸ General ▸ Restore sessions gains Live sessions with its unavailability reason.

## Platform exemptions

- **Hidden-pane GPU release (#492).** Upstream frees a hidden pane's Metal swap chain and bumps its
  libghostty pin to `683d8db` for the upstream hidden-surface work. Linux pins `11b9a6e` with three local
  patches, and its deck deliberately keeps a stable `GtkGLArea` per session so Dashboard can mirror live
  surfaces without reparenting. Moving the pin is a separate change with its own patch rebase and rendering
  re-test.
- **macOS permission documentation.** The TCC entitlement families, the Files & Folders prompts and the
  usage strings describe a mechanism Linux does not have.
- **Signing, notarization, DMG and Homebrew release notes.** Upstream release mechanics.

## Validation

Run in the pinned Swift 6.3.2 container:

- `agtermCore`: 2979 tests pass.
- `agterm-linux`: 226 tests pass, including the new `LinuxZmxTests`.
- `swiftlint lint --strict`: clean.
- `swift build` and `swift build -c release` in `agterm-linux/`: clean.
- `scripts/check-linux-core-boundary.sh v0.26.0` and `check-linux-cli-drift.sh`: pass.
- `scripts/test-linux-ui.sh`: all AT-SPI checks pass.
- `scripts/stage-linux.sh`: payload carries `libexec/zmx`, and the launcher exports `AGTERM_ZMX`.

By hand, under Xvfb with an isolated state directory:

- Live sessions: `restore mode` reports `requested live, active live`; the pane reads `backedByZmx` and
  its foreground resolves through the daemon rather than the attach client; `zmx list` joins the daemon
  against the claiming pane; the process survives a quit; the next launch reattaches to the same daemon
  and still reports the running command.
- Switching to fresh shells and relaunching reaps the detached daemon and the process inside it.
- `session.swap`: the two terminals exchange sides, both stay alive and accept input, and no GL context
  error is logged. Its first form segfaulted — unparenting a pane host drops the paned's last reference —
  which is why both hosts are referenced across the reparent.

## Known local limitation

`git fetch` against GitHub fails inside the `swift:6.3.2-noble` image on this machine, for the pinned
libghostty as much as for zmx, while the same fetch succeeds on the host. The vendored caches cover it
locally; the branch CI run is what exercises the fetch path.
