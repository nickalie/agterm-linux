# Linux v0.21.0 catch-up

## Range

- Previous Linux parity base: upstream `v0.20.2`
  (`4d263a7cb714baaec8ca05feb0bdf97f6490c777`)
- Target parity base: upstream `v0.21.0`
  (`9e8105015f83f0b7a4a2040b7f6ff19851644265`)
- Integration branch: `linux-port`
- Merge commit: `e14ebb0` (`chore(upstream): merge v0.21.0`)
- Upstream range is 28 commits, all released in `v0.21.0`.
- `upstream/master` carries 8 further commits (terminal AX exposure, sidebar name copy, HUD corner
  placement/text color). This catch-up is tag-bounded and ships none of them.

The v0.20.2 catch-up was never released, so `linux-v0.21.0` is the first Linux release since
`linux-v0.19.0` and carries both ranges.

## Inventory

### Portable core and shared artifacts

Inherited from upstream; no Linux code required.

- The whole host-free HUD model: `Hud.swift` (`HudSpec`, `HudSpinner`, `HudPosition`, `HudPanelSize`,
  `HudLayout`), `ControlDispatcher+Hud` validation, the `ControlProtocol` commands and `ControlHudNode`
  read-back, `Session`'s slot state, and `agtermctlKit`'s `session hud` subcommands (#361).
- `InterfaceMetrics`: the palette/switcher text sizes, panel fitting, and the terminal-area centering
  offset, plus `AppSettings.interfaceFontSize` and its clamp (#367).
- Lossy snapshot decoding, so a hand-edited or partly-corrupt state file can no longer wipe the persisted
  tree: `sidebarMode` (#360), `focusedWorkspaceIDs`, every `Snapshot` optional, and the nested/legacy
  focus-migration guards.
- `WindowLibrary` reopening the window the user exited from rather than `windows.first`.
- Restore correctness in the store: a captured foreground command replays exactly once, the capture copy
  is gated on `launchRestore`, `loadStore` rewrites a non-bootstrap load that carried captures, and
  orphan recovery strips one-shot captures while leaving a sticky `session.restore` pin armed (#370).
- `AppStore+Snapshot` extraction and the `AppStore+PendingClose` follow-up.

The Linux `agtermctl` target builds on the shared `agtermctlKit`, so `session hud open|update|close`,
`--spinner`/`--spinner-style`, `--position`, `--detail` and their validation reach Linux with no
downstream edit.

### Carried portable core fix

- `agterm/Resources/hud/hud.sh` measures `${#line}` under a forced `LC_CTYPE=UTF-8`, which counts code
  points in bash-as-`/bin/sh` but **bytes in dash**, the `/bin/sh` on Debian/Ubuntu. Every non-ASCII
  message and every spinner glyph (all five styles are non-ASCII) therefore centers wrong on Linux, by
  one column per extra UTF-8 byte. Upstream's own `HudHelperTests` fail on Linux for exactly this.
  The fix is portable and upstreamable.

### GTK parity work

- Host `session.hud.*` in the Linux `ControlActions`: resolve the staged helper, measure the pane and the
  terminal cell from the GTK font description, write the body file atomically, and take the session-wide
  overlay slot through the existing `openHud`/`updateHud`/`closeHud` store API (#361).
- Stage `agterm/Resources/hud/` into the Linux payload beside `agent-status`, and resolve it at runtime
  through the same candidate list.
- Route every Linux passivity gate through `Session.programOverlayActive` instead of raw `overlayActive`:
  deck cover gates, focus routing, scratch focus, zoom target resolution, and the overlay-close refocus.
- Honor `interfaceFontSize` in the GTK palette, control picker, and session switcher, and expose it on
  the Preferences ▸ Appearance page beside the sidebar size (#367).
- Dismiss a shown scratch instead of flipping `isSplit` behind it, and make the press inert under a full
  program overlay, in `AppController.toggleSplit` (`29c4711`). Control `session.split` is unchanged.
- Scope the `windowWillClose` foreground capture to the last open window, matching upstream's
  `openIDs() == [windowID]` guard: Linux captures on every window close today, which is the stale-replay
  path #370 closed.
- Update Linux CI and release ancestry pins to `v0.21.0`.

### Platform-specific adaptations and exemptions

- The `performable:` clipboard-bind fix (`d6ff63d`) edits `agterm/Resources/ghostty-defaults.conf`, a
  macOS bundle resource. Linux emits its own defaults from `GhosttyDefaults.baseConfLines`, which carries
  no `super+key_*` clipboard binds at all — GTK and the keymap own copy/paste there — so there is no
  fall-through to key encoding to fix.
- The titlebar-hairline work (`e962e84`, `7688ac4`) is `NSTitlebarContainerView` /
  `NSToolbarFullScreenWindow` suppression around a 1px `chromeText` separator the SwiftUI views draw.
  The GTK window has no such separator: `AdwHeaderBar` is dropped whole in hidden mode, so nothing is
  left painting on the window's top edge.
- The dark-launch environment fix (#378) corrects a libghostty config rebuild triggered by a conditional
  `theme = light:,dark:` config. Linux never emits a conditional theme — `AppController.ghosttyLines(for:isDark:)`
  resolves the side before the config is built, and `GhosttySurface.create` applies the captured
  appearance to the app before `ghostty_surface_new` — so no rebuild replays the config files and no
  `env_vars`/`initial_input`/`command` is dropped.
- macOS Reduce Motion / Reduce Transparency, the Dock-icon bounce, and the notification sound remain
  AppKit accessibility and Dock APIs with no portable GTK counterpart.
- GTK4 still exposes no reliable restorable x/y placement, so Linux continues to omit window `geometry`.

## Found by the gates, not by the inventory

- The surface factory still read the persisted `foregroundCommand`, which upstream had emptied in favour
  of a transient pending slot, so NO restored command ran. Only the AT-SPI `surface-lifetimes` scenario
  caught it; every unit test and the whole build were green.
- `aFailedStripDisarmsBothPanesInsteadOfLeavingAReplayItCouldNotRecord` makes a write fail with a `0500`
  mode, which root ignores — and root is what the CI container runs as. It now asserts nothing when the
  directory is still writable rather than pin the opposite branch.

## Not verified interactively

The HUD panel was validated by build, unit tests and the AT-SPI suite, which asserts no pixels for it:
the Pango cell measurement, the two-axis panel geometry, `--position`, and the spinner styles still want a
hands-on pass in a real session before the release is announced.
