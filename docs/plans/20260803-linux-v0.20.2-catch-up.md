## Inventory

### Portable core and shared artifacts

Inherited from upstream where upstream owns them; no Linux code required.

- Freshly created workspaces become current, plus the reselection/focus rework that keeps the active
  session inside the visible set and narrows close-reselection to the applied workspace filter (#329,
  `146747d`).
- Control-character sanitizing for session/workspace/window names and `--cwd` (#347, #354).
- `session.type` no longer requires `--select` to reach an unrealized surface; the wait moved into the
  shared protocol/CLI layer (#351).
- Oversized-request rejection before connecting, on the shared `agtermctlKit` client (#340).
- `DashboardTarget` pane-ref parsing (`<id>:left` / `<id>:right`) and its promotion-follow behavior
  (#334).
- Pick label-only matching for caller-supplied rows, caller ordering, `--query`, and itemless pickers
  (#339).
- `CommandRestore` foreground reporting for panes with no job-control shell (#358).
- `FirstRunWelcome` due-decision and copy, plus the `welcomeShown` and `workspaceRowClickExpands`
  settings fields (`4ca62a3`, #342).
- Repo-wide comment-brevity rewrite and the unused-`Foundation`-import cleanup (#323, `c3e4c8d`).

The Linux `agtermctl` target builds on the shared `agtermctlKit`, so every CLI-level change above reaches
Linux without a downstream edit.

### Carried portable core fix

- `agtermctlKit/SocketClient.writeAll` now writes with `MSG_NOSIGNAL` under `canImport(Glibc)`.
  Upstream's #340 fix guards `SO_NOSIGPIPE` behind `canImport(Darwin)` because Glibc has no such socket
  option, which left Linux with no SIGPIPE suppression at all: upstream's own new
  `writeToHungUpPeerThrowsInsteadOfDying` test killed the Linux test process with signal 13 instead of
  failing. This is portable, minimal, and upstreamable.

### GTK parity work

- Conform the Linux `ControlActions` to the pane-scoped overlay signatures and route
  `session.overlay.*` through the pane-aware store API (#343).
- Mute the terminal behind floating panels and mute a pane overlay on the unfocused split pane, matching
  the extended backdrop-mute setting (#327, `0f0d641`).
- Honor `workspaceRowClickExpands` in the GTK sidebar and expose it in Preferences (#342).
- Present the first-run welcome as a native dialog offering the skill and status-hook installers, gated
  on the shared `FirstRunWelcome.isDue` decision (`4ca62a3`).
- Accept `<id>:left` / `<id>:right` dashboard pane refs in the Linux dispatcher and dashboard
  presentation (#334).
- Apply label-only matching for caller-supplied picker rows in the GTK palette (#339).
- Restore an even split when the GTK split divider is double-clicked (`d056ebd`).
- Update Linux CI and release ancestry pins to `v0.20.2`.

### Platform-specific adaptations and exemptions

- The macOS Help-menu wording for the welcome dialog does not apply; Linux routes the same installers
  through Preferences ▸ Integrations, so the Linux dialog names that surface instead.
- The AppKit resize-cursor work over the sidebar and split dividers (#326, #344) has no Linux
  counterpart: GTK4 sets the pointer cursor from the `GtkPaned` handle itself, so there is no
  tracking-area overrun to correct.
- The sidebar status-blink-across-row-reloads fix (#335) is an `NSOutlineView` row-recycling artifact.
  The GTK sidebar animates from the controller, not a recycled row view, so no Linux change is needed.
- The focus-set workspace weight and the Settings disclosure-triangle caption (`24b2970`, `b35dd34`) are
  AppKit presentation details already handled natively by the GTK sidebar and Preferences pages.
- macOS Reduce Motion / Reduce Transparency remain AppKit accessibility APIs; GTK follows desktop
  settings and does not emulate them.
- GTK4 still exposes no reliable restorable x/y placement, so Linux continues to omit window `geometry`
  while supporting resize, maximize, fullscreen, and minimize.
